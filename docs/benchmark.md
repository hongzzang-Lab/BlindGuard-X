# 공개 데이터셋 평가 결과 (MOT15 · SOMPT22)

Cam1 Vision의 입력 방식 네 가지를 공개 보행자 추적 데이터셋에 그대로 돌려, 정확도와 Raspberry Pi 5에서의 프레임당 처리 시간을 잰 기록이다. 2026-11-26 측정.

> 순위표 제출이 아니다. 정답이 공개된 학습용 구간만 썼고, 지표는 `bench/mot_bench.py`가 직접 계산했다.

## 조건

| 항목 | 값 |
|---|---|
| 장치 | Raspberry Pi 5 Model B (GPU 없음) |
| 검출 | YOLO26n, NCNN, 입력 416×416, conf 0.10 |
| 추적 | ByteTrack (`bgx/bytetrack.py`) |
| 설정 | 시뮬 시연 값(`simdemo/site_sim.json`) 그대로. 데이터셋에 맞춘 조정 없음. 매 프레임 YOLO |
| 지표 | CLEAR MOT (IoU 0.5), IDF1 |
| 처리 시간 | 프레임 하나를 처리하는 시간. 영상 읽기 제외. FPS = 1000 / 평균 ms |

### 비교한 방식 (모델·추적기·설정은 같고 YOLO에 넣는 화면만 다름)

| 이름 | 내용 |
|---|---|
| FULL | 프레임 전체를 416으로 줄여 YOLO 1회 (기준선) |
| ADAPTIVE | 움직임과 추적 위치를 모두 감싼 큰 ROI 하나, YOLO 1회 |
| OURS (ROI별 추론) | 사람(ROI)마다 따로 잘라 YOLO를 ROI 수만큼 |
| OURS_PACKED | ROI들을 416×416 한 장에 모아 YOLO 1회 (최종 구조) |

## 확인된 것

1. **사람마다 ROI를 만들어 크게 보면 더 많이 찾는다.** FULL → OURS(ROI별 추론)에서 Recall이 62.6 → 72.9 (MOT15), 19.5 → 33.0 (SOMPT22). IDF1도 52.9 → 59.8, 27.9 → 42.6.
2. **Packing은 그 이득의 일부를 추론 한 번으로 가져온다.** ROI별 추론 대비 속도 2.2배(11.5 → 25.2 FPS, MOT15), 2.8배(8.7 → 24.3 FPS, SOMPT22). FULL 대비 MOTA +3.6, +5.5.
3. OURS_PACKED는 ADAPTIVE와 속도가 같고, 합계 MOTA가 +1.8 (MOT15), +3.9 (SOMPT22).

## 한계

1. **속도는 FULL이 가장 빠르다.** ROI를 만들고 모으는 데 프레임당 약 7~8 ms가 더 든다. 이 방식으로 얻는 것은 속도가 아니라 정확도다.
2. **Packing을 하면 Recall 이득의 일부를 잃는다** (MOT15 72.9 → 67.4, SOMPT22 33.0 → 26.1). 사람이 많을수록 한 장에 모으려면 ROI를 줄여야 한다.
3. **SOMPT22-13에서는 OURS·OURS_PACKED가 FULL보다 크게 나쁘다** (MOTA 33.4 → 16.7 / 18.2). 원인은 확인하지 않았다.
4. **SOMPT22 구간 10·11·12는 PACKED가 90% 이상 전체 화면으로 되돌아갔다.** 그 구간에서는 Packing을 평가했다고 보기 어렵다.
5. **MOT15 PETS09-S2L1에서는 OURS_PACKED의 MOTA가 ADAPTIVE보다 낮다** (77.9 vs 81.3). 오검출이 늘었다.
6. **SOMPT22에서는 ID 변경 횟수가 늘었다** (182 → 243 / 295). 더 많은 사람을 잡은 영향이 섞여 있어, ID 유지의 근거로는 IDF1만 쓴다.
7. **높이 60 px 미만 보행자의 Recall은 ROI를 써도 2~4%** (SOMPT22). 작은 보행자 문제가 풀린 것은 아니다.
8. 절대 점수가 낮다. 가장 작은 YOLO를 416 입력으로 썼고, 순위표의 방법들과 비교할 수 없다.
9. 입력을 키운 FULL(예: 640)과는 비교하지 않았다. "같은 정확도를 더 싸게 얻는가"는 아직 재지 않은 질문이다.
10. SOMPT22는 구간당 앞 10초, 1회 실행. 통계적 유의성은 주장할 수 없다.
